Las 6 dimensiones de calidad

El proyecto utiliza reglas para evaluar diferentes características de los datos.

📌

Completitud

Comprueba que los campos obligatorios no contengan valores nulos.

🔑

Unicidad

Evita registros duplicados e identificadores repetidos.

✅

Validez

Verifica formatos, patrones y valores permitidos.

🔗

Consistencia

Comprueba que los campos relacionados tengan coherencia.

🎯

Exactitud

Evalúa que los valores estén dentro de rangos realistas.

⏱️

Oportunidad

Comprueba que la información esté actualizada.

Instalación y ejecución

Sigue estos pasos para ejecutar el proyecto localmente. 

# Clonar repositorio
git clone https://github.com/JuanS3/taller-m5u5-calidad-cicd.git

# Entrar al proyecto
cd taller-m5u5-calidad-cicd

# Crear entorno virtual
python -m venv .venv

# Activar entorno (Linux / macOS)
source .venv/bin/activate

# Instalar dependencias
pip install -r requirements.txt

# Ejecutar pipeline
python -m src.pipeline.run_pipeline

Automatización CI/CD

El repositorio implementa dos flujos de GitHub Actions para controlar la calidad antes de publicar los datos.

🔄

CI - Desarrollo

Se ejecuta mediante push y pull requests. Valida los datos con un umbral mínimo del 95% y genera reportes como artefactos.

🚀

CD - Producción

Se activa mediante etiquetas de versión. Exige un 100% de calidad y genera un GitHub Release con los datos certificados.

Construyendo datos confiables

La calidad no debe ser una tarea manual al final del proceso. Debe formar parte de cada etapa del ciclo de vida de los datos.
